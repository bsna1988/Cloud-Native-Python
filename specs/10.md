# ADR 0010: Explicit Aggressive Correction of Book Text Fields

- **Status:** Accepted
- **Date:** 2026-10-31

## Context

Book titles and other text can contain OCR mistakes, and existing records may
also have been entered manually with spelling errors. Automatic recognition
uses conservative local correction, but users need an option to retry
correction on already stored or manually edited text without making a network
request.

Correction can damage legitimate names, invented words, and mixed-language
titles. The existing first-party dictionaries are intentionally small and
cannot confidently correct every word. Any broader correction should
therefore be explicitly user initiated and reviewed before persistence.

## Decision

Add an **Aggressively fix spelling mistakes** action to the Android book edit
screen. It applies the local JSymSpell corrector independently to the title,
author, and description currently shown in the form. It does not modify the
barcode or release date, which are identifiers/structured data rather than
prose.

The explicit action accepts a unique closest dictionary suggestion up to three
edits away. Existing automatic OCR correction remains limited to one edit.
Already-known words and ambiguous suggestions remain unchanged. Preserve
capitalization and punctuation where possible.

The action only updates the in-memory edit form. It does not trigger a catalog
lookup, save the book, or alter the persisted record. The user must review the
corrected values and explicitly save them. Correction works locally and
offline; no text is sent to a service.

## Consequences

### Positive

- Users can attempt stronger corrections on existing OCR and manually entered
  records without spending catalog API calls.
- The correction covers all editable prose fields while leaving barcode and
  release-date values intact.
- Existing automatic correction behavior remains conservative.
- Explicit review and save keep potentially incorrect suggestions reversible.

### Negative

- The correction quality is limited by the bundled first-party French,
  English, and Ukrainian lexicons; unsupported words may remain unchanged.
- A three-edit suggestion can be wrong, especially for proper nouns or unusual
  book titles. Users must review every modified field before saving.

## Alternatives considered

### Automatically apply aggressive correction to every scanned or edited book

Rejected because incorrect changes to names, invented words, or valid
multilingual text could be persisted without the user's review.

### Send text to an online grammar or language model service

Rejected because it would require network access, consume a provider quota,
and upload book metadata. The correction action should remain free and local.

### Keep all correction limited to one edit

Rejected because it leaves some obvious multi-character OCR errors uncorrected.
The stronger threshold is available only through an explicit edit-screen
action and leaves the existing automatic path unchanged.
