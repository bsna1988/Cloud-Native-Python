# ADR 0007: Conservative Local Correction of OCR Text

- **Status:** Accepted
- **Date:** 2026-10-30

## Context

The Android bookshelf flow uses on-device OCR to extract text candidates from
book spines. OCR can confuse visually similar characters and produce words
that are close to the printed title but incorrect. For example, it may read
`contes magiques` as `eontes magiqugs`, or `MES ORIGAMIS` as `MES ORIBAMIS`.
These small errors make otherwise useful candidates harder to search and
require manual correction.

Book titles often contain proper nouns, invented words, foreign-language
words, abbreviations, and names that are absent from ordinary dictionaries.
An aggressive spellchecker can therefore make a valid title less accurate.
The shelf image also contains books in more than one language, so a single
language dictionary is insufficient. Correction must not turn a plausible
OCR guess into apparently certain metadata.

## Decision

Add a conservative, offline text-correction stage after OCR extraction and
before candidates are shown in the existing review flow. Automatically apply
high-confidence corrections to individual OCR words; this stage must not
identify books, invent missing text, or automatically import candidates.

Use the MIT-licensed JSymSpell library for deterministic SymSpell
suggestions. Use bundled first-party French, English, and Ukrainian word lists
as its dictionaries; do not include external dictionary data unless its
commercial-use license and provenance have been verified. Search only within
one Damerau-Levenshtein edit and apply a correction only when there is one
unique closest candidate across the supported word lists. Preserve a token
already present in any list. Do not rank by frequency or guess the language.
The dictionaries and algorithm must work without network access and must not
send OCR text or images to a hosted service. Include JSymSpell's MIT license
notice with the Android app.

### Correction behavior

- Modify the OCR title with high-confidence word corrections before it enters
  the review list. Do not force a correction when language support is
  uncertain, the token is unknown, or multiple alternatives are similarly
  plausible.
- Apply corrections to words, not by replacing a whole title with a dictionary
  phrase. Preserve token order, punctuation, and the original capitalization
  where possible.
- Do not use frequency alone to replace a token. Proper names, series names,
  acronyms, and invented words may be valid even when absent from the word
  list; leave ambiguous or unsupported tokens unchanged.
- Retain the original OCR title whenever a correction is applied and show it
  alongside the corrected title in the review UI. The user can edit the
  corrected result; never create a book without the user's confirmation.
- Bound candidate generation and processing per image. Correction must not
  block the UI thread, retain image data, or change the existing local-only
  image-recognition data flow.

### Evaluation

Evaluate correction against the existing bookshelf fixture and a labeled set
of OCR examples containing both errors and valid unusual title words. Report
results separately for raw OCR and corrected output, including exact and
approximate title matches, word-level corrections that fix an error, and valid
words incorrectly changed. Include French and other languages present in the
evaluation set.

Do not count a correction as a recognition success unless it matches the
reference text. Keep the existing raw OCR score and require the corrected
fixture score not to regress from the raw score. Report corrected words that
match the reference separately from changed words absent from it, and include
tests that keep valid unusual words unchanged. Retain the raw OCR benchmark so
improvements are measured against the current 18-of-32 title baseline rather
than replacing or weakening it.

## Consequences

### Positive

- Common OCR character confusions can be corrected locally without requiring
  a larger vision model or an online service.
- JSymSpell supplies the spelling-suggestion algorithm under the permissive
  MIT license; first-party word lists avoid bundling dictionary data with
  unclear commercial-use terms.
- Keeping the raw OCR alongside corrected titles makes corrections
  transparent and reversible.
- A conservative threshold limits damage to proper nouns, uncommon titles,
  and words in unsupported languages.
- A labeled evaluation can show whether the correction stage improves actual
  title accuracy instead of merely making text look more fluent.

### Negative

- Local dictionaries and language-specific ranking data add maintenance and
  may increase the app's size.
- Dictionary coverage is incomplete, especially for names, new releases,
  invented words, and mixed-language titles. The current first-party
  dictionaries are intentionally small.
- Incorrect corrections remain possible, so the review and editing flow is
  still necessary.
- Building a representative labeled dataset and choosing correction
  thresholds requires additional test and evaluation work.

## Alternatives considered

### Use the platform keyboard spellchecker

Keyboard spellcheckers are designed for user-entered prose, may use
device-dependent dictionaries or settings, and do not provide a controlled,
repeatable correction policy for scanned text. Rejected in favor of JSymSpell
with bundled dictionaries so behavior is deterministic across devices and can
be evaluated against the bookshelf fixture.

### Propose suggestions instead of automatically correcting

This leaves users to apply many obvious OCR fixes manually. Rejected in favor
of applying only narrow, high-confidence corrections while keeping the raw
OCR visible during review.

### Leave OCR text uncorrected

This avoids false corrections but leaves common, recoverable OCR character
errors for users to fix manually. Retain it as the fallback whenever a
correction is unsupported or ambiguous.
